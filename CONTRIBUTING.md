# Contributing Guidelines

## Workflow

1. Create a feature branch from `dev`.
2. Commit focused changes with meaningful messages.
3. Push the feature branch to GitHub.
4. Open a pull request targeting `dev`.
5. Add a clear pull request description.
6. Review another member's pull request and leave at least one comment.
7. Merge only after review feedback has been addressed.

## Commit Messages

Use short, descriptive commit messages that explain the purpose of the change.

Examples:

- `Add task list feature`
- `Improve dashboard layout`
- `Resolve README sprint focus conflict`

## Branch Naming

- Feature work: `feature/task-list`, `feature/ui-dashboard`
- Conflict practice: `conflict/sprint-a`, `conflict/sprint-b`

## Pull Request Checklist

- The branch is up to date with `dev`.
- The description explains the change.
- Review feedback has been added.
- The change has been tested manually.
